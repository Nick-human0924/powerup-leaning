# 增量导入与恢复

1. 选择教材库资料、实际课次或反馈。界面教材导入的课次复选框只有家长主动选中才建立课次；反馈在独立页面归档。
2. 本机对文件计算SHA256，已存在的同一文件提示重复。PDF使用pdfjs worker逐页生成预览和文字，图片验证解码。扫描页明确需要OCR/人工，不根据文件名推断印刷页。
3. OCR/语义建议只能在勾选本次云端授权后请求。服务端Zod校验结构；来源证据与置信度供核对，不能把扩展句型称为原文。没有内容时保留待核对，不发布空材料。
4. 逐页审核教材身份、单元、section、印刷页、表达、中文含义与原话证据。UI中的「核对并发布」是明确的人工验证；所有当前新内容按人工核对发布。
5. 原子写入教材/来源/知识点/生成题/可选课次/审计，刷新UI。确定性技能ID由教材身份、单元、类型和规范表达生成；相同文件/页/技能幂等；跨文件同书完全相同页像素复用。不同版本不混合。
6. 修改已有技能解释/来源保留技能ID并增加version、写入以前版本审计。旧题和观察不会删除。表达本身改变会产生新技能，保留旧技能，避免历史悄悄重映射。

错误页不成为可发布内容；可以重新检查文件，取消后不写入学习成绩。取消/失败原因应明确显示。附件可能已保存在本机用于重试，占用空间；清除全站资料前先备份，浏览器配额不足时停止写入并提示。

并发操作采用IndexedDB事务与串行队列；导入事务失败不会部分发布快照。大附件独立保存，JSON仅存引用，不假装存在云端同步。跨设备需要另外迁移原文件和录音。

当前九份真实 PDF 已完成本地逐页渲染和 RapidOCR：90 页、9 个原始文件哈希，保留逐行坐标/置信度与 OCR 页脚候选。主词汇和语言练习经过原页核验；当前种子为 Hello–Unit7（p.89 截止）、82 个页段、196 个知识点、197 道练习。没有模型凭证，云端语义/音频服务仍未做真实准确率验收。

## 本机批量检查工具

```powershell
$taskPython = "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe"
& $taskPython scripts/inspect-textbook.py
```

该命令读取 `imports/materials/`，输出私有 `imports/processed/textbook-pages.json` 和 `public/textbook-pages/`，依据哈希恢复已检查页面。依赖 pypdf、Pillow、rapidocr_onnxruntime、Poppler，当前电脑已经配置。它只完成文字识别，不把 OCR 文本直接当作已验证知识点。

`scripts/build-textbook-import.py` 是本次已核验 Power Up p.4–89 的整理器，运行它会重建本次教材种子。它不是任意新书的自动教研工具。未来教材先检查原页，再通过「教材 → 导入」逐页人工录入或授权已配置的视觉服务获取建议，核对后发布；不需要修改前端常量。新教材不会清空既有观察。
